AutoLang for Linux: tester build

Version 0.6.0 · first Linux test build · 23 November 2026

AutoLang fixes text you typed in the wrong keyboard layout. Type akuo while you meant Hebrew and it becomes שלום; carry on typing and you are in Hebrew. On Linux it is an IBus input method, the same mechanism Chinese, Japanese and Korean input uses, so it needs no root process and no special permissions.

Thanks for testing. Before you start:

  • It is built for Ubuntu 24.04 or later with the standard GNOME desktop, Wayland or X11, on 64-bit Intel or AMD. Other GNOME distributions with IBus (Debian, Fedora) may work; tell me if you try.
  • It corrects between English and Hebrew. Other languages come later, see Other layouts.
  • Setup takes three commands. Testing takes as long as you like.

1. Download

Download the .deb (amd64)

About 23 MB. SHA-256, if you want to check it (sha256sum autolang_0.6.0-tester1_amd64.deb):

2. Install

In a terminal, from the folder you downloaded to:

sudo apt install ./autolang_0.6.0-tester1_amd64.deb

Use apt, not dpkg -i, so the few libraries it needs come along. It installs exactly this, and nothing runs until you select AutoLang as your keyboard:

/usr/lib/autolang/autolangThe program: engine and command line in one file, with .NET built in.
/usr/bin/autolangA link to it, for the commands below.
/usr/share/ibus/component/autolang.xmlTells IBus that AutoLang exists and how to start it.
/usr/share/autolang/, /usr/share/doc/autolang/Icon and licence.

No service, no root process, no input group, no udev rule, no network access. IBus starts AutoLang as your own user when you pick it, and it stops with your session.

3. Turn it on

As your own user (no sudo):

ibus restart
autolang enable
autolang doctor
  1. ibus restart makes IBus notice the new input method. Logging out and back in does the same.
  2. autolang enable adds AutoLang to Settings → Keyboard → Input Sources and selects it. Your other layouts stay in the list. To do it by hand instead: + Add Input Source, then search for AutoLang (it is listed under Other).
  3. autolang doctor checks every step and prints what to fix. It should end with Everything looks right.
  ok   ibus-daemon is running
  ok   IBus knows the AutoLang engine
  ok   AutoLang is a GNOME input source
  ok   AutoLang is the current input source
  ok   the AutoLang engine is running
  ok   layout us: English (United States) [us], Latin, word list en
  ok   layout il: עברית (ישראל) [il], Hebrew, word list he

How it behaves on Linux

This is the one real difference from Windows and Mac. There, AutoLang watches your layouts and switches between them. Here, AutoLang is the layout: you select it once, and it types both English and Hebrew itself. The top bar shows EN or HE for the language it is typing in now.

  • It switches language by itself when it corrects a word.
  • To switch by hand, tap Shift twice with nothing typed, or use Type in … in the top-bar keyboard menu.
  • Pause corrections in the same menu keeps typing in the current language with no corrections.
  • Super+Space still switches to your ordinary layouts. AutoLang does nothing while one of them is selected.
  • The word you are typing stays "in progress" until you finish it, which is how AutoLang can fix it without deleting anything. Some apps may underline it while you type. Tell me where that looks wrong.

4. What to try

  1. Open Text Editor. With the top bar showing EN, type akuo and a space. It should become שלום and the top bar should show HE.
  2. Now press the keys h-e-l-l-o and a space (יקךךם). It should become hello .
  3. Right after a correction, tap Shift twice quickly to undo it. AutoLang remembers that word and leaves it alone from then on.
  4. To convert a word that was not corrected, tap Shift twice before you type the space.

Then use it normally for a while. Good places to try:

  • Firefox and Chrome: a search box, Gmail, a Google Doc, WhatsApp Web.
  • Electron apps: Slack, Discord, VS Code. Also Telegram and LibreOffice.
  • Pressing Enter right after a mistyped word, instead of a space. Fixing a typo with Backspace in the middle of a word.
  • Typing fast, and mixing English and Hebrew in one sentence.

Password fields and terminals are typed in the current language but never corrected.

5. Report back

Please send:

  • The output of autolang doctor. It includes your Ubuntu version and whether you are on Wayland or X11.
  • What worked, what didn't, and in which apps. A word changed when it shouldn't have been (or the other way round) is the most useful thing you can tell me.
  • The log, ~/.local/state/autolang/autolang.log. It records timing, corrections and the kind of field (normal, password, terminal). It never records what you typed.

You can send it however you like, or open an issue on GitHub.

Known rough edges

  • Converting selected text (select, tap Shift twice) is not in the Linux build yet.
  • There are no per-app exclusions yet, and the menu is in English only.
  • Keys AutoLang does not type itself (the keypad, AltGr characters) come out as on a US keyboard.
  • For a second or so after you log in, AutoLang types but does not correct, while it loads its word lists.
  • Apps that do not use IBus at all (some games, old Java apps) get plain US typing while AutoLang is selected.

Other layouts

AutoLang's settings are a plain file, ~/.config/autolang/settings.json. On first run it copies the layouts you had in GNOME (or English and Hebrew if you had fewer than two). To change them, edit "layouts" with XKB names, then run ibus restart:

{
  "layouts": ["us", "ru"],
  "paused": false,
  "exceptionWords": []
}

This build ships word lists for English and Hebrew only. Other layouts are typed but not corrected yet (the Windows version downloads their lists; the Linux build cannot yet). autolang layouts shows what each key types on each layout, and autolang try "akuo " runs keys through the engine without IBus, which is handy for reporting a wrong decision. exceptionWords lists the words you undid; delete one to let AutoLang correct it again.

Under the hood

The engine and the decisions are the same code as on Windows and Mac: word frequency lists and character statistics, all local, no AI service. The Linux part talks to IBus over D-Bus and reads your layouts with libxkbcommon. It is all MIT licensed, in src/AutoLang.Linux. To build the package yourself you need the .NET 8 SDK; packaging/linux/build-deb.sh wraps the published binary.

Uninstall

autolang disable
sudo apt remove autolang

autolang disable takes AutoLang out of your input sources and leaves the others as they were. To remove its settings and log too:

rm -rf ~/.config/autolang ~/.local/state/autolang
